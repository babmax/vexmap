## PR 2: хук кадра для съёмки

Черновик контракта, детали уточняются по коду `gfx.rs` перед отправкой:

- Клиентский хук `capture_frame_size`, контракт `replace`: мод может задать размер кадра и цель «в текстуру, не в окно» на
  один кадр. Возвращает `None`, если мод ничего не просит, и тогда путь скриншотов работает как сейчас.
- Готовый кадр мод забирает там же, где сейчас: в `hand_drawn`, до HUD.
- Тест: кадр с запросом не попадает в окно, следующий кадр попадает. Рядом с существующими тестами `draw_scaled_frame`.

Почему не отправляем сейчас: панорамы в Фазе 9, а контракт лучше показать вместе с работающим модом.

## PR 3: Horizon-клиент за прокси

Причина из S5: сервер читает brand до ответа `SelectKnownPacks`, а через Velocity brand к этому моменту не пришёл
(предположение, порядок пакетов не записывался). Перед PR нужно:

1. Записать порядок пакетов на стенде через Velocity, подтвердить причину.
2. Обсудить в issue, как Horizon хочет решать: ждать brand дольше, перечитывать после конфигурации или доверять заголовку от
   прокси с modern forwarding.

Это затрагивает допуск и сеть ядра, поэтому сначала issue, потом код. Для нашего мода PR не блокирующий.

## Временные миксины

Правило: миксин на внутреннюю функцию только с комментарием `TEMPORARY(horizon#…)` в `horizon-mixin.toml` и строкой в
таблице выше. CI ежедневно собирает мод против `main` Horizon (`upstream.yml`) и сразу показывает, если цель исчезла.

| Цель | Где | Убрать когда |
|---|---|---|
| `Game::native_custom_payload_from_client` | `mods/vexmap` | Пин на ревизию, где `custom_payload_from_client` получил номер API |
| Поле `Game::screen` (запись `Screen::Playing`) | `map_screen.rs::apply_requests` | Принят PR 4 |
