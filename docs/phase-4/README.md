# Фаза 4: ресурс-пак, игровой интерфейс и изоляция от тика

Начата 2026-11-08. Цель фазы: обязательный ресурс-пак, окно карты, миникарта, настройки и пресеты, замер цены мода для тика.
Карта здесь схематичная: суша, сетка и игроки. Тайлы, тема и глобус приходят в Фазе 5.

## 1. Архитектура

```text
 сервер региона                                          клиент
 Hello ─► Welcome(player) ─► PackGate.offer ── ResourcePackPush ──► подсказка, загрузка, применение
 resource_pack_status ◄──────────────────────────────── статус ◄───┘
   отказ, сбой, тайм-аут ─► native_kick с объяснением

 /map ─► perform_command ─► Message::OpenMap ──────────► native_mod_screen_open

 клавиши, мышь, кадр ─► vexmap_ui::Ui ─► список Op, 10–30 Гц ─► map_screen.rs: native_fill, native_quad, native_text
```

- `ui.rs` не знает об игре: настройки, пресеты, вид карты, геометрия и списки рисования. Тот же файл собирается как крейт `vexmap-ui`, поэтому тесты и бенчмарки идут без сборки Horizon.
- `map_screen.rs` только читает игру и воспроизводит списки. Хуки ввода получают `&Game`, поэтому открытие и закрытие экрана ждут ближайшего кадра.
- Положение игрока берётся на клиенте (`native_player`), сервер о нём не спрашивают. Свой маркер отфильтрован по UUID из `Welcome`.
- Список рисования перестраивается с частотой пресета, в промежутках повторяется готовый. Перетаскивание и зум перестраивают сразу.
- Настройки пишутся через 500 мс после последнего изменения в отдельном коротком потоке, через временный файл и переименование. Повреждённый файл не мешает игре: плохая строка получает значение по умолчанию.

## 2. Дерево файлов

```text
crates/vexmap-resourcepack/      сборка пака: все изображения рисуются кодом, архив воспроизводим
crates/vexmap-ui/                Cargo-обёртка над ui.rs, бенчмарк
mods/vexmap/mixins/vexmap/
  ui.rs                          логика интерфейса, только std
  map_screen.rs                  экран карты, миникарта, кнопка в меню паузы
  proto.rs                       PackGate, TickMeter, Welcome.player, OpenMap (протокол 2)
  hooks/*.rs                     12 новых адаптеров
tools/dev/phase4_test.py         стенд: пак, интерфейс, цена для тика
```

## 3. Протокол и настройка

| Изменение | Значение |
|---|---|
| `PROTOCOL` | 2 |
| `Welcome` | Добавлен `player: u128`, UUID игрока по данным сервера |
| `kind` 11 `OpenMap` | Сервер → клиент, пустое тело |

| Переменная сервера | Значение |
|---|---|
| `VEXMAP_PACK_URL`, `VEXMAP_PACK_SHA1` | Адрес пака и его SHA-1, строчными. Без них сервер пак не просит и пишет об этом в лог. Заданы неверно: то же, с причиной. На боевых серверах обязательны |
| `VEXMAP_BENCH_ADMIT_ALL` | Только для нагрузочных тестов с ботами: допускает всех без мода. В продакшене не задавать |

Пак собирается командой `cargo run -p vexmap-resourcepack -- <папка>` и входит в релиз (`release.yml`). Хостинг файла остаётся за оператором. Сейчас пак весит 2,6 КБ.

## 4. Решения

**Статус всех ADR этой фазы: предложено, ждёт подтверждения владельца.**

### ADR-017. Как выдавать пак

| Вариант | Плюсы | Минусы |
|---|---|---|
| **`native_send_resource_pack` после `Welcome`** | Подсказка уже в игре, текст и таймауты наши, ответы слышит хук | Игрок с модом успевает войти до применения пака |
| `resource-pack` в `server.properties` | Штатно, отказ обрабатывает сам сервер | Ответы до входа хук v1 не слышит, у мода нет контроля. Настройка размазана по всем серверам |

**Выбор: выдача модом.** Пак нужен только для значков, поэтому ждать его до допуска незачем. Отказ обрабатывает сам клиент: для обязательного пака он отключается с сообщением «This server requires a custom resource pack» раньше, чем сервер услышит ответ. Текст нашего отказа видят те, у кого не загрузился файл или истёк срок.

Хук `resource_pack_status` версии 1 не передаёт номер пака, а v2 нет в каталоге именованных хуков. Мод отправляет ровно один пак, поэтому хватает v1 (правило 11).

### ADR-018. Чем рисовать окно карты в этой фазе

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Хелперы GUI (`native_fill`, `native_quad`, `native_text`)** | Текст, порядок с HUD и масштаб GUI бесплатно. Не нужен свой конвейер | Нет настоящего обрезания, каждый элемент это вершины в общем батче |
| Свой проход wgpu в `hand_drawn` (как S1) | Нужен для глобуса и тайлов | Ради прямоугольников и текста это преждевременно, подписи всё равно нужен GUI |

**Выбор: хелперы GUI сейчас, проход wgpu для тайлов и глобуса в Фазе 5.** Обрезание по окну сделано в геометрии: линии режутся по кругу и прямоугольнику, клинья диска алгоритмом Сазерленда–Ходжмана.

### ADR-019. Где хранить настройки

| Вариант | Плюсы | Минусы |
|---|---|---|
| **`config/vexmap.cfg` через `native_config_dir`** | Один текстовый файл, игрок может его прочитать, штатное место | Свой разбор |
| `native_set_setting` | Готово | По файлу на ключ в папке данных мода, неудобно для 21 поля |

**Выбор: один файл.** Формат `ключ=значение`, новые поля не ломают старые файлы.

### ADR-020. Кнопка в меню паузы

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Кнопка в левом верхнем углу меню паузы** | Видна сразу, не перекрывает колонку меню | Хелпера закрытия меню паузы нет, нужно исключение из правила 11 |
| Только клавиша и `/map` | Только именованные хуки | Промт требует кнопку |

**Выбор: кнопка**, с записью `game.screen = Screen::Playing` как временной мерой (ровно то же делает `horizon-ctl resume`). Запись и PR описаны в [horizon-prs.md](../phase-1/horizon-prs.md), отправка только с согласия владельца.

### Цена для тика

`python tools/dev/phase4_test.py ticks`, боты идут пешком, допуск снят через `VEXMAP_BENCH_ADMIT_ALL`, игроки в одной стране, 200 тиков на отчёт, 6 отчётов:

| Ботов | p50, мкс | p99, мкс | Максимум, мкс |
|---:|---:|---:|---:|
| 1 | 1 | 11–31 | 28–317 |
| 20 | 1 | 38–63 | 41–258 |

Бюджет p99 < 500 мкс выполнен на 20 игроках. Это время всего `server_tick` мода: снимок игроков (2 Гц), почтовые ящики, допуск, пересылка кадров. В отчёт попадают и первые секунды со входом ботов.

Что этот замер не показал:

- Больше 20 игроков. При 50 игроках на сервер региона линейная оценка даёт около 160 мкс p99 [оценка].
- Цену отправки в конце тика: `native_send_custom_payload_to_player` только ставит в очередь. S3 показал, что по MSPT её не отделить от шума.
- `payload_from_client` и вход игрока: они вне `server_tick`.
- Ботам приходят кадры одной страны, но боты не отвечают рукопожатием, поэтому `PackGate` под нагрузкой не работал.

## 7. Риски и ручные проверки

- На боевых серверах нельзя забыть `VEXMAP_PACK_URL`: без него сервер пускает игроков без пака и только пишет строку в лог. Войдёт в предрелизный чек-лист Фазы 14.
- Запись `game.screen` это внутреннее поле Horizon. Если поле переименуют, упадёт сборка `upstream.yml`, а не игра.
- `VEXMAP_BENCH_ADMIT_ALL` отключает допуск. Его нельзя задавать на серверах с игроками.
- `horizon-clients-only` за Velocity по-прежнему выключен (ADR-007), отличить клиент помогает только рукопожатие мода.
- Снимки экрана со стенда лежат в `.deps/run/phase4/shots` и не коммитятся: на них текстуры Minecraft.
