# Фаза 0: аудит Horizon

Дата: 2026-11-07. Проверен `horizon-rust/horizon`, ветка `main`, коммит `2ebf00a0281c592f79191e76fce0e7d522c6f425`
(`NATIVE_HOOKS_API = 411`, Rust 1.95, wgpu 30.0.1). Также просмотрены `horizon-mods` (мод Minimap) и список `native/`.

Как читать метки:

- **[док]** написано в документации Horizon этого коммита.
- **[код]** видно в исходниках или в `native-hooks.json`.
- **[замер Horizon]** цифра из бенчмарков самого Horizon, не наша.
- **[оценка]** мой расчёт или вывод. Ничего не запускалось.
- **[прототип]** ответ можно получить только запуском, см. раздел 7.

**Ограничение аудита.** Это проверка по документам и коду. Игра, сервер и моды не собирались и не запускались,
своих замеров нет: на стенде нет ни Git, ни Rust.

## 1. Расхождения с промтом

| Что в промте | Что на самом деле | Следствие |
|---|---|---|
| Около 12 документированных hook points | API 411, 432 хука и 174 хелпера в `native-hooks.json` [код] | Большая часть «недостающих» точек уже есть |
| Канала для своих пакетов нет | `horizon:mod_net` с API 40: `native_net_send_to_player`, `native_net_send_to_server`, `native_net_from_client`, `native_net_from_server` [док] | Транспорт не требует PR |
| Своя отрисовка требует новых хуков или правок ядра | `native_world_drawn` и `native_hand_drawn` отдают `wgpu::Device`, `Queue`, `CommandEncoder`, цель кадра, глубину и матрицы [код] | Форк ради глобуса, вероятно, не нужен [прототип] |
| Лончер не собирает моды для выделенных серверов | `horizon-launcher native-build FOLDER --server-output DIR --version TAG --trust-native-code` [док] | Ручной конвейер не нужен. Кросс-компиляции нет: сервер для Linux собирается на Linux |
| Надо придумать способ пускать только Horizon-клиентов | `horizon-clients-only = true` в `server.toml`, раздел `[properties]` [док]. Проверяется `minecraft:brand`, его можно подделать | Базовый допуск готов, наше рукопожатие только добавляется |
| У каждого мира своя граница | Сейчас в Horizon одна граница на все уровни: `native_world_border` отвечает одинаково для трёх измерений [док] | Границу каждого мира мод хранит сам |
| Граница мира круглая (допускается в промте) | `native_world_border` отдаёт прямоугольник `[min_x, min_z, max_x, max_z]` [док] | Ванильная граница квадратная. Круглую границу должен обеспечивать мод, см. ADR-006 |
| Цель 5000+ игроков, архитектуру выбрать | Один сервер Horizon держит около 50 игроков при 20 TPS. Цель самого Horizon в планах: 200 на 8 ядрах [замер Horizon] | **Главный риск проекта**, см. раздел 3 и ADR-001 |

Проверить заявленные в промте 7–12 минут сборки у игрока и 281 дифференциальный тест пока не удалось.

## 3. Масштаб: главный вывод

Замеры самого Horizon [замер Horizon]:

| Ботов | Машина | TPS | MSPT avg | Трафик на игрока | Память |
|---:|---|---:|---:|---:|---:|
| 50 | Mac 14 ядер, общий, шумный | 20,0 | 28,7 мс | 76,5 КБ/с | 1,5 ГБ |
| 100 | Mac 14 ядер, общий, шумный | 14,3 | 79,2 мс | 95,4 КБ/с | 2,05 ГБ |
| 20 | EPYC, 4 ядра | 20 TPS держит | 36,0 мс | | 1,2 ГБ |
| 60 | EPYC, 4 ядра | Не держит | 62,0 мс | | 1,8 ГБ |

- Основная работа тика идёт в **одном потоке**. Цель из `server-next.md`: 200 игроков на 8 ядрах, 300 при распределении
  по трём измерениям. Это план, а не текущее состояние.
- С живыми игроками может быть тяжелее: на официальном сервере 28 игроков дают 32,7 мс на тик, половина уходит на мобов.

Что это значит для 5000 игроков [оценка]:

| Игроков на сервер | Серверов на 5000 | Комментарий |
|---:|---:|---|
| 40 | 125 | Сегодня, с запасом |
| 50 | 100 | Сегодня, предел по замеру |
| 200 | 25 | Если Horizon выполнит свой план, около 200 ядер |

Только игровой трафик на 5000 игроков: 3,0–3,8 Гбит/с [оценка из 76–95 КБ/с].

**Один непрерывный мир на 5000 игроков на Horizon сегодня невозможен, и ни одним кодом карты это не исправить.**
Прокси Velocity поддерживается штатно [док]. Единого мира на нескольких серверах в Horizon нет, переход между серверами
означает смену сервера. Решение в ADR-001.

## 4. Панорамы

Камеру можно поставить куда угодно через `native_camera_pose`, а кадр скопировать в `native_world_drawn`. Но игрок видит
этот же кадр: второго вида вне экрана нет [код].

Съёмка куба занимает 6 кадров, при 60 FPS это около 100 мс. Шаг 16 блоков даёт одну съёмку примерно каждые 3,7 с пешком и
2,9 с бегом [оценка]. Если снимать в основной кадр, игрок будет регулярно видеть рывок. Если подставлять прошлый кадр,
картинка будет замирать. Для фоновой съёмки это неприемлемо, поэтому нужен второй проход рендера. См. ADR-005.

Также в документации сказано, что загрузка чанков остаётся привязана к игроку, поэтому снять можно только то, что уже
видно клиенту.

## 5. Транспорт

Лимиты `horizon:mod_net` [док]: 30 000 байт в сообщении, 32 сообщения за тик в каждую сторону на игрока. Потолок
19,2 МБ/с на игрока [оценка], на практике он намного выше бюджета.

Подводные камни [док]:

- Сообщения от клиента приходят в хук на следующем тике, в игровом потоке. Отправка уходит в конце тика.
- Значит, sidecar отправляет данные игрокам через тик. Перенос между потоками должен быть O(1), с ограниченной очередью.
- Всё, что прислал клиент, не проверяется: это обычный ввод игрока.
- Неясно, делится ли лимит в 32 сообщения между всеми модами.
- Проход канала через Velocity в документах не описан [прототип].

## 6. Сборка и распространение

- Лончер собирает мод на компьютере игрока, первая сборка показывает доверительное предупреждение. Предсобранный
  horizon-mixins пока в списке «Left to do» [док].
- Мод для реестра проходит ручную проверку, последующие релизы проверяются автоматически. Откат через `revoked.toml` [док].
- Рукопожатия совместимости сервера и мода нет (#6304, не реализовано) [док], делаем своё.
- Кэш сборки по умолчанию ограничен 30 ГиБ после сборки; пик может быть выше [док].
- Согласие `--trust-native-code` записывает решение оператора, и документация прямо запрещает агенту его давать [док].
  **Эту команду запускает только владелец.**
- У `horizon-mods` на GitHub лицензия не определяется, у самого Minimap и у шаблона мода MIT [код]. Лицензия `horizon` и
  `horizon-mixins` MIT подтверждена через API GitHub. Наш MIT совместим [оценка, не юридическое заключение].

## 7. Что осталось проверить запуском

Каждый пункт закрывает конкретный риск. Прототипы одноразовые и в релиз не идут.

| № | Прототип | Вопрос | Чем определяется успех |
|---|---|---|---|
| S1 | Глобус в экране мода через `native_hand_drawn` | Можно ли рисовать поверх мира, не ломается ли картинка от постэффектов и затемнения фона | Шар 60 FPS на baseline, GUI поверх него |
| S2 | Второй вид вне экрана | Можно ли получить его миксином без форка | 6 граней без рывка для игрока |
| S3 | Канал `mod_net` | Сквозная пропускная способность, цена для тика, проход через Velocity | Бюджет трафика, нагрузка на тик p99 < 0,5 мс |
| S4 | Серверный движок с модом | Работает ли `--server-output` и бенчмарк | Запуск на Linux, чистый замер |
| S5 | Два сервера за Velocity | Сколько длится переход между регионами, что происходит с каналом и ресурс-паком | Измеренное время, карта не теряет данные, пак не перезагружается |
| S6 | Сборка клиента | Реальные время и место на диске для игрока | Цифры для инструкции |

  виртуальные диски. `CreateVirtualDisk` падает с `0xC03A0014` на VHD и VHDX, на C: и E:, драйвер `vhdmp` с загрузки не запускался.
