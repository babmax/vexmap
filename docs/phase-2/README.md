# Фаза 2: данные и локальный API

Начата 2026-11-08. Цель фазы: одно ядро данных, через которое идут все долговременные правки карты, и локальный API над ним для
RP-модов. Здесь первый срез: игроки и роли, выключатели модулей, журнал изменений. Страны, места и вики ложатся на тот же путь
в своих фазах.

## 1. Архитектура

```text
 мод сервера региона ─┐
 RP-моды (HTTP)      ─┼─► vexmap-sidecar: REST на 127.0.0.1 ─► vexmap-core ─► SQLite (стенд) / PostgreSQL (прод)
 RP-моды (крейт)     ─┴──────────────────────────────────────► Core::…            │
                                                                                  └─ journal: порядок = порядок коммитов
```

- REST не принимает решений: разбирает запрос, ограничивает скорость и зовёт `Core`. Крейт и HTTP поэтому ведут себя одинаково.
- Каждая правка это одна транзакция: `journal_head.seq + 1`, сама правка, запись в журнал. Правка и её запись не разделимы.
- Роль игрока читается из базы и никогда не берётся из запроса (правило 8). Игрок, которого база не знает, прав не имеет.
- В каждой записи журнала есть регион (ADR-001). Общего состояния в памяти игрового сервера нет.
- Позиции игроков здесь не ходят: это поток Фазы 3, а не долговременные правки.

## 2. Решения

### ADR-010. Хранилище

**Статус: предложено, ждёт подтверждения владельца.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **`sqlx` с драйвером `Any`, запросы проверяются во время работы** | Один слой запросов для SQLite и PostgreSQL, код стенда и прода общий, как требует промт | Только общие типы (`TEXT`, `BIGINT`), запросы не проверяются при компиляции. Схема в двух каталогах |
| `rusqlite` и `tokio-postgres` за своим трейтом | Точный контроль и родные типы каждой базы | Каждый запрос написан дважды, а значит расходятся стенд и прод |
| Только PostgreSQL и на стенде | Никаких различий между базами | Промт разрешает стенд без сервера СУБД, а локально PostgreSQL сейчас нет |

**Выбор: `sqlx` + `Any`.** Геоданным нужен PostGIS, такие запросы появятся в Фазе 7 и будут отдельным слоем с вариантом для каждой базы.

### ADR-011. Порядок журнала

**Статус: предложено, ждёт подтверждения владельца.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Счётчик в одной строке, который каждая правка увеличивает первым действием** | Номера без дыр, порядок журнала равен порядку коммитов, читатель с курсором ничего не пропустит | Писатели идут строго по одному |
| `BIGSERIAL` | Параллельная запись | Коммиты завершаются не в порядке номеров: читатель `seq > N` молча теряет строки |

**Выбор: счётчик.** Правки карты редкие (заявки, модерация, границы), а массовые потоки сюда не идут. Цена одной записи ещё не
измерялась: если война с массовой сменой чанков упрётся в этот предел, у её потока будет своя таблица и пакетная запись (Фаза 11).

Повтор запроса с тем же `Idempotency-Key` от того же автора возвращает прежний `seq` и ничего не меняет. Отказ и правка без
изменений в журнал не пишутся и дыр в номерах не оставляют.

### ADR-012. Локальный API

**Статус: предложено, ждёт подтверждения владельца.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **REST и JSON на `axum`** | Вызывается из любого языка, проверяется через `curl`, зависимостей мало | Медленнее бинарного протокола |
| gRPC (`tonic`) | Строгие схемы, потоки | Сборка `protoc`, труднее проверять вручную. Для редких правок выгоды нет |

**Выбор: REST.** Подписку на журнал через поток можно добавить позже, сейчас читатель опрашивает `GET /v1/journal?after=N`.

Защита при доверенных локальных модах (допущение 10): адрес только loopback (иначе процесс не стартует), `Host` только loopback
(против DNS rebinding из браузера), тело до 64 КиБ, token bucket на клиента, не больше 256 имён клиентов.

## 3. Схема и API

Таблицы: `journal_head`, `journal`, `players`, `feature_flags`, см. [миграции](../../crates/vexmap-core/migrations/). Схемы SQLite и
PostgreSQL сейчас совпадают дословно и должны совпадать по смыслу.

Запись требует заголовков `X-VexMap-Client` и `Idempotency-Key`, а `X-VexMap-Region` необязателен. Чтение под `/v1` требует
`X-VexMap-Client`. Поле `actor` означает, что вызов идёт от имени игрока и решает его роль. Без него действует сам локальный мод.

| Запрос | Тело | Что делает |
|---|---|---|
| `GET /healthz` | | Состояние и номер последней записи |
| `GET /v1/players/{uuid}` | | Игрок |
| `PUT /v1/players/{uuid}` | `name` | Записать вход. Только локальный мод |
| `PUT /v1/players/{uuid}/role` | `role`, `categories`, `actor?` | Сменить роль. Игрока может ещё не быть |
| `GET /v1/features?region=` | | Включённые модули и маска для `Hello.features` |
| `PUT /v1/features/{module}` | `enabled`, `region?`, `actor?` | Выключатель. Флаг региона важнее глобального, не заданный модуль выключен |
| `GET /v1/journal?after=&limit=` | | Записи по порядку, до 1000 за раз |

Правила ролей: владелец и локальный мод меняют любые роли, админ только ниже админа, остальные никакие. Последнего владельца снять
нельзя. Категории бывают только у модератора и обязательны для него. Выключатели меняют админ, владелец и локальный мод.

Настройки sidecar: `VEXMAP_DATABASE_URL`, `VEXMAP_API_ADDR`, `VEXMAP_OWNER_UUID`, `VEXMAP_API_RATE`, `VEXMAP_API_BURST`, `RUST_LOG`.
Путь SQLite пишется без `//`: `sqlite:C:/data/vexmap.db?mode=rwc`, иначе разбор адреса потеряет букву диска.

## 4. Тесты

| Проверка | Где |
|---|---|
| `vexmap-core`: 13 сценариев на настоящей базе, включая 16 параллельных писателей и журнал без дыр; юнит-тесты правил и типов | CI, три ОС |
| Те же сценарии на PostgreSQL 17, кроме двух только для SQLite и разбора адреса (11 из 13) | CI, задача `postgres` |
| `vexmap-sidecar`: маршруты целиком, отказы, лимиты, настройки | CI, три ОС |

## 5. Состояние на 2026-11-08

| Шаг | Статус |
|---|---|
| Ядро, SQLite | Готово, тесты проходят на Windows |
| REST API | Готово. Бинарник проверен запуском: владелец создан при старте, флаг и журнал работают, чужой `Host` и публичный адрес отвергаются |
| PostgreSQL | **Не проверен.** Локально сервера нет, задача `postgres` в CI ещё не запускалась |
| Связь с модом | Нет. Мод ещё не вызывает sidecar, `AdmissionGate` получает маску как раньше. Это начало Фазы 3 |
| Крейт для RP-модов | `vexmap-core` можно подключить, но контракт ещё не версионирован |
| Страны, места, вики, откат по истории | В своих фазах. Журнал уже хранит `before` и `after` для отката |

## 6. Риски

- **Локальный API без аутентификации.** Любой процесс на машине может вызвать его как локальный мод. Это принятое допущение 10, но на
  проде на хосте должны работать только наши процессы.
- **Цена записи и лимиты по умолчанию не измерены** (500 в секунду, запас 1000). Числа временные, бенчмарк нужен до Фазы 14.
- **Соединение с PostgreSQL без TLS:** подходит, только если база на том же хосте или в частной сети. Для выноса на другой хост
  нужно включить TLS в `sqlx`.
- **Резервные копии и экспорт** ещё не сделаны, они входят в Фазу 15.
