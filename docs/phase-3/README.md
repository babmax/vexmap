# Фаза 3: realtime-слой и транспорт данных

Начата 2026-11-08. Цель фазы: позиции и данные карты доходят до игроков по каналам стран, а скрытое клиенту не отправляется.
Здесь первый срез: сервер региона берёт выключатели модулей из базы, не затрагивая игровой поток.

## 1. Архитектура среза

```text
 база ─► vexmap-sidecar ◄── GET /v1/features?region=R каждые 5 с ── поток vexmap-sidecar в моде
                                                                        │ AtomicU64
 Hello клиента ─► тик сервера ─► AdmissionGate: клиент & регион ◄───────┘ Welcome.features
```

- Игровой поток только читает атомарную переменную. Сеть, таймауты и разбор ответа живут в отдельном потоке (правило 7).
- Sidecar недоступен: остаётся последняя известная маска, поток пробует снова через 5 секунд. Допуск от sidecar не зависит.
- Sidecar ни разу не ответил: все модули выключены.
- Регион задаёт `VEXMAP_REGION`, адрес `VEXMAP_API_ADDR`. Оба значения проверяются, адрес только loopback.

## 2. Решения

### ADR-013. Связь мода с sidecar для настроек

**Статус: предложено, ждёт подтверждения владельца.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Опрос REST из отдельного потока, на чистом `std`** | Тот же API, что у RP-модов, в Cargo.lock Horizon ничего не добавляется | Изменение доходит до 5 с. Свой минимальный HTTP-клиент |
| Постоянный бинарный канал уже сейчас | Сразу основа для позиций | Большая работа ради значения, которое меняется редко |
| Читать базу прямо из мода | Без sidecar | Драйвер СУБД в игре, падение базы затрагивает игру |

**Выбор: опрос.** Он подходит только для редких настроек. Для позиций нужен постоянный локальный канал, это следующий шаг фазы.

Клиент разбирает ответ поиском `"mask":`, без JSON-парсера. Это безопасно, потому что остальные поля ответа это проверенный регион и
фиксированные имена модулей. Контракт закреплён тестом `vexmap-link` против настоящего sidecar.

## 4. Тест на стенде

2026-11-08, Velocity, серверы `a` и `b` с модом, sidecar, клиент Horizon `6560641`. Модуль `tiles` включён глобально и выключен в `b`.

| Проверка | Результат |
|---|---:|
| Маска региона при допуске, сервер `a` | `0x2` |
| Маска региона при допуске, сервер `b` | `0x0` |
| Переходы `a → b → a → b`, допуск на новом сервере | 3 из 3, 1,09–1,97 с после команды `/server` |
| Sidecar убит: новый допуск на `a` | Да, 0,22 с, маска осталась `0x2` |
| Отключения клиента с модом | 0 |
| Клиент без мода | Отключён через 10,11 с, `NoHello` |

Что этот тест не показал:

- Цену для тика: она не измерялась, хотя в тике появилось только чтение атомарной переменной.
- Причину разницы во времени перехода: в Фазе 1 было 0,45–0,52 с, здесь 1,09–1,97 с. Логин на новом сервере занимал 1,06–1,94 с, то есть
  время ушло до входа, а не на допуск. Прогонов мало, сравнивать их рано.
- `Welcome.features` с ненулевым значением: клиент пока не реализует ни одного модуля (`FEATURES = 0`), поэтому пересечение равно нулю.
  Сама операция проверена юнит-тестами.

## 5. Второй срез: поток игроков в sidecar

```text
 тик, раз в 500 мс: native_server_players ─► swap в Mailbox ─► поток vexmap-feed ─► TCP loopback ─► vexmap-sidecar
                                             (одна партия,      кодирует и пишет                     │ PositionStore в памяти
                                              новейшая вытесняет)                                    └ новые игроки ─► Core::record_player
```

- Партия это полный список допущенных игроков региона, 2 раза в секунду, даже пустой. Кого в ней нет, тот ушёл. Событий входа и выхода нет,
  поэтому терять и повторять после обрыва нечего.
- Игрок попадает в партию только после `Welcome`, так что клиент, которого выкинут за отсутствие мода, в базу не запишется.
- С выключенным модулем `realtime` партия несёт только UUID и имена: база узнаёт игрока, а позиции не передаются.
- Позиции живут только в памяти sidecar и базы не касаются. Отключился сервер региона, и регион исчезает из таблицы.
- Новое соединение региона вытесняет старое, а закрытие старого не трогает новое.
- Позиции квантуются до 1/8 блока, поворот до 1/256 оборота. В локальном канале передаются абсолютные значения, дельты нужны на пути к игрокам.
- Формат: `u32` длина, затем тело. Первое сообщение `Hello` с регионом. Лимиты: 1 МиБ на сообщение, 4096 игроков в партии, 256 соединений,
  минимум 50 мс между партиями, 15 с тишины закрывают соединение.
- Чтение для локальных модов: `GET /v1/positions?region=`. Адрес канала `VEXMAP_FEED_ADDR`, по умолчанию `127.0.0.1:7879`, только loopback.

### ADR-014. Как тик передаёт позиции

**Статус: предложено, ждёт подтверждения владельца.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Почтовый ящик на одну партию: `Mutex::try_lock` и обмен буферов** | Без `unsafe`, тик не ждёт никогда, память ограничена одной партией, коалесинг получается сам собой | Формально не lock-free: при занятом ящике один снимок пропускается, следующий придёт через 500 мс |
| `AtomicPtr` с обменом указателей | Настоящий lock-free | `unsafe` в моде, который работает с полными правами игрока, ради случая, который и так не блокирует тик |
| Ограниченная очередь событий на игрока | Буквально как в промте | Нужны слоты на игрока, вытеснение и восстановление после переполнения. Полный список решает это проще |

**Выбор: почтовый ящик.** Промт просит bounded MPSC с коалесингом. Здесь один производитель и коалесинг всей партии, требования «не ждать, не расти,
хранить только последнее» выполняются.

### Замеры

`cargo bench -p vexmap-link --bench feed`, Windows, стенд:

| Операция | Поток | Время, 200 игроков |
|---|---|---:|
| `Mailbox::publish` | Тик | 21 нс |
| `encode_batch` | `vexmap-feed` | 8,1 мкс |

Бенчмарк не включает `native_server_players` и перекладывание результата в `PlayerSample`. Это основная цена для тика, она O(игроков) с аллокациями
внутри Horizon, 2 раза в секунду, и пока не измерена. Бюджет тика p99 < 0,5 мс для этого пути не подтверждён.

|---|---:|
| После переходов `a → b → a → b` игрок в таблице региона `b` | 1 |

юнит-тестами. Переподключение после гибели sidecar проверено на настоящем сокете в `vexmap-link`, на стенде sidecar не перезапускался.

## 6. Состояние на 2026-11-08

| Шаг | Статус |
|---|---|
| Выключатели модулей из базы в рукопожатии | Готово, проверено на стенде |
| Запись игроков в базу при входе | Готово, проверено на стенде |
| Уже допущенные игроки при смене флага | Не получают новую маску до следующего входа. Флаг `realtime` для потока читается при каждом снимке |
| Сбор позиций 2 Гц, квантование | Готово, проверено на стенде |
| Постоянный локальный канал мод → sidecar с коалесингом | Готово, проверено на стенде. Обратного направления пока нет |
| Дельты и раздача позиций игрокам | Не начато |
| Каналы стран, interest management, кластеры | Не начато. Нужно членство игрока в стране, хотя сами страны в Фазе 7, поэтому минимальная таблица появится здесь |
| Backpressure, снапшот и дельты при реконнекте, шина между серверами | Не начато |

Игрок, переходящий между регионами, может на одну партию оказаться в обоих. Убрать дубль надо при раздаче игрокам.
