# ПРОЕКТ
Мод для сервера Minecraft Java 26.3 на Horizon (Rust-переписывание Minecraft, github.com/horizon-rust/horizon). Цель: полноценная аналогия Google Maps/Google Earth для нашего игрового мира, целиком внутри игры. Сайта нет: карта, GPS, панорамы, вики, места, отзывы, страны, войны и модерация доступны только в клиенте Minecraft.
Мир: вымышленный RP-мир со странами, игроки со всего мира. На боевом сервере у мира есть граница, для тестов используется бесконечный мир. Карта круглая во всех мирах. Размер и форму границы мод определяет сам.
Нагрузка: цель 5000+ одновременных игроков; на старте ожидаются сотни тестеров и тысячи игроков онлайн в первые месяцы. Железо игроков: средние ПК.
RP-моды (экономика, политика и выборы, армия и войны) будет писать Claude, карта должна стать их общей основой.
Выкатка: всё сразу (все модули в одном релизе), поэтому обязательны предрелизные нагрузочные тесты и выключатели функций (feature flags) для каждого модуля.
Запуск: домашний ПК (мощный, много ядер и ОЗУ) используется как стенд для разработки и тестов. Перед открытием для игроков переезд на VPS/выделенный сервер, бюджет на железо не ограничен, нужна полная защита от DDoS на уровне провайдера.
Код мода открытый (open-source).
Реализация: серверный нативный мод + клиентский нативный мод Horizon, при необходимости форк клиента (см. «Реальность Horizon» и «Выбранный путь»). На сервер допускаются только Horizon-клиенты, ванильные Java-клиенты нет. Ресурс-пак сервера обязателен.

# ЖЁСТКИЕ ПРАВИЛА
1. Ничего не выдумывай. Если не уверен в API Horizon — скажи об этом и найди в исходниках.
2. Сначала Фаза 0 (аудит и бюджеты), код — только после неё.
3. Каждое решение: 1–2 альтернативы, выбор и причина.
4. Код production-уровня: типы, обработка ошибок, тесты, без unwrap()/panic в рантайме.
5. Чужие данные и ассеты Google не используем: иконки, шрифты и стили рисуем оригинальные или берём из свободных наборов с совместимой лицензией. «Как в Google Maps» означает функциональность и визуальный язык, а не копирование.
6. Оптимизация только на основе измерений: любое утверждение о скорости подкрепляй бенчмарком (criterion), профилем (flamegraph/perf) или нагрузочным тестом.
7. Мод не имеет права заметно замедлять тик игры и FPS клиента: вся тяжёлая работа вне игрового потока.
8. Сервер авторитетен: права, видимость, секретность и любые изменения данных проверяются на сервере, клиенту не доверяем (в том числе присланным скриншотам и панорамам).
9. Открытый код: не коммить секреты, конфиги-шаблоны вместо реальных значений, лицензия совместима с лицензией Horizon (MIT) и зависимостей.
10. Horizon: следуй CLAUDE.md, AGENTS.md и CONTRIBUTING.md репозитория (vanilla first, маленькие PR около 500 строк с тестами, `tools/pr_ready.py`). Никогда не коммить файлы игры, ассеты Mojang, декомпилированный код и подготовленные ресурсы (`.local/`). Ресурс-пак и иконки только оригинальные.
11. Используй только именованные hook points (`"hooks": N`), а не сырые цели mixin, чтобы мод переживал обновления Horizon. Недостающие hook points добавляй PR-ами в horizon-rust/horizon, пока PR не принят держи патчи в нашем репозитории.
12. Правила Mojang для серверов: внутриигровая валюта не продаётся за реальные деньги, не выводится в реальные деньги, платных случайных предметов нет. Это касается рынка, цен, продвижения мест и всей RP-экономики.

# РЕАЛЬНОСТЬ HORIZON (проверено по документации 2026-11-07, перепроверь по исходникам в Фазе 0)
Источники: README horizon-rust/horizon, docs/mods.md, docs/native-mods.md, docs/smp.md.
- Horizon: Minecraft Java 26.3, переписанный на Rust (клиент на wgpu/Vulkan, 281 дифференциальный тест против ванили), лицензия MIT. Не содержит кода и ассетов Mojang, игроку нужен свой аккаунт Microsoft с Java Edition. Репозитории: horizon (клиент, `horizon-server`, лончер), horizon-mixins, horizon-native-mod-template, horizon-mods (реестр и официальные моды).
- Два вида модов: контентные `.hmod` (данные и ассеты, без кода) и нативные `.hnmod` (бандлы horizon-mixins: Rust-код, который меняет исходники игры до компиляции).
- Нативные моды экспериментальные и не в песочнице (полные права игрока). Лончер собирает их на компьютере игрока: первая сборка около 7–12 минут, до 1.5–2 ГБ на сборку, плюс тулчейн Rust до 1.7 ГБ на Windows. Мод привязан к коммиту Horizon либо к версии hook points (`"hooks": N`, hook points только добавляются).
- Документированные hook points: 2 (панель предметов и рецепты, клиент), 3 (жизненный цикл мира), 4 (тик сервера), 8 (команды и игроки), 9 (предметы игрока), 10 (серверные меню-сундуки), 11 (частицы), 12 (подсказки предметов). Черновики: чтение блоков на сервере, изменения соседних блоков, изменения блоков. Планируются: взаимодействия с блоками и предметами, урон, телепорт, защита территорий, строки сайдбара и TAB.
- Официальные клиентские нативные моды: FPS Counter, Keystrokes, Zoom, Minimap, Recipes, Coordinates HUD. Игра оставляет в ядре то, что должно быть быстрым (например, отрисовку карты миникарты), а мод выбирает параметры. Вывод: для нашей отрисовки карты, 3D и панорам нужны новые hook points или правки ядра.
- Мультиплеер: при подключении к серверу работают только клиентские хуки, протокол не меняется. Документированного канала для своих пакетов между серверным и клиентским модом нет.
- Серверы: `horizon-server` принимает и ванильных Java-игроков, и Horizon. Серверный мод встраивается в движок сервера: `horizon-mixins apply` с бандлом, затем `cargo build --release --no-default-features -p horizon-client`, затем `[engine] path` в конфиге `horizon-server`. Документ native-mods.md говорит, что лончер пока не собирает нативные моды для выделенных серверов, а официальный сервер делает это вручную (мод SMP). Перепроверь, что конвейер работает на текущем коммите.
- Образец серверного мода без установки у игроков (SMP): команды с автодополнением, меню-сундуки `generic_9x6` как кнопки (клики решает сервер), звуки, титры, action bar, boss bar, scoreboard. Данные в папке мира (`world/horizon-smp/`), атомарная запись JSON, `audit.log`. Используй как образец структуры и тестов (и `tools/server_bench.py` с ботами).
- Реестр модов: нужен публичный исходный код и лицензия, проверка `cargo horizon-mod check`, подписи minisign (Ed25519), SHA-256, ручная проверка нативных модов, возможность отзыва (`revoked.toml`).
- Агентное управление: `horizon-ctl` (и `horizon-ctl mcp`) запускает игру, читает состояние как JSON и действует как игрок. Используй для интеграционных тестов.

# ВЫБРАННЫЙ ПУТЬ И МАТРИЦА РЕАЛИЗУЕМОСТИ
Решения владельца: серверный нативный мод + клиентский нативный мод (сборка через лончер). На сервер допускаются только Horizon-клиенты. Ресурс-пак с сервера обязателен. Новые hook points активно предлагай в основной репозиторий Horizon (PR). Если 3D-глобус и панорамы нельзя сделать через хуки клиента, немедленно делаем форк клиента (MIT) со своими готовыми сборками клиента и сервера.
1. Серверный нативный мод: данные, права, видимость и секретность, модерация, заявки, история, API для RP-модов, команды, меню-сундуки как запасной интерфейс, частицы, звуки, boss bar/action bar. Собирается в движок сервера нашим CI на каждый релиз Horizon.
2. Клиентский нативный мод: кнопка и клавиши, окна карты, HUD, миникарта, GPS-стрелка, экраны вики, заявок и модерации, настройки и пресеты, скриншоты, локальная история посещений. Собирается лончером у игрока.
3. Транспорт данных сервер→клиент (порядок предпочтения): (a) кастомные payload-пакеты через новые hook points (предложить PR), (b) отдельный авторизованный канал данных от sidecar к клиентскому моду (токен сессии выдаёт игровой сервер), (c) запасной путь через ванильные средства (чат, меню-сундуки, boss bar) для базовых функций.
4. Ворота «клиент»: если собственная отрисовка (карта, глобус, 3D-здания, панорамы) не выражается через хуки, выбирается форк клиента. Решение фиксируется в документе архитектурных решений (ADR) в Фазе 0 с оценкой работ и рисков и подтверждается владельцем.
5. Ресурс-пак: обязательный, выдаётся сервером автоматически. Иконки, элементы интерфейса, шрифтовые глифы для заголовков меню. Только оригинальные ассеты, никаких ассетов Mojang и Google. Размещение пака на статическом хостинге (по URL с контрольной суммой), версионирование, поведение при отказе игрока (отключение с понятным сообщением). Проверь, что клиент Horizon поддерживает серверные пакеты ресурсов.
6. Только Horizon-клиенты: способ отличить Horizon-клиента с нашим модом от ванильного (рукопожатие клиентского мода, brand клиента или другое) и отклонять остальных при входе с понятным сообщением. Проверь возможность в Фазе 0.
7. Распространение: исходники открыты, `.hnmod` публикуется в реестре horizon-mods (после ревью) с подписью minisign и инструкцией, как игроку собрать и установить. При форке собственные релизы клиента и сервера. Автообновление клиентского мода означает обновление из реестра и повторную сборку лончером (или обновление форка).
Матрица реализуемости (проверь в Фазе 0 и отметь: S = серверный мод, K = клиентский мод через хуки, F = форк клиента):
- Данные, права, приватность, секретность, заявки, очередь модерации, история и снапшоты, Discord-вебхук, API для RP-модов: S.
- Команды, уведомления, сирена, события, boss bar и action bar: S (плюс K для красивого вывода).
- Меню-списки (места, заявки, модерация) как запасной интерфейс: S (меню-сундуки).
- Кнопка, горячие клавиши, настройки и пресеты, миникарта, HUD, GPS-стрелка, экраны вики и редакторы: K (нужны hook points, часть через PR).
- Плоская и круглая 2D-карта с тайлами, редакторы границ и дорог: K (нужна собственная отрисовка, возможно новые hook points).
- 3D-глобус, 3D-здания, панорамы, плакат высокого разрешения: F, если через хуки нельзя.

# ФУНКЦИОНАЛ

## Карта и интерфейс
- Стиль: схематичный, как Google Maps. Вода, биомы и суша заливаются плоскими цветами, дороги линиями, здания контурами и 3D-моделями, мягкий рельеф (hillshade). Реалистичный спутниковый слой не нужен.
- Тема: автоматически по игровому времени суток (день — светлая, ночь — тёмная), с плавным переходом.
- Иконки мест и объектов: в стиле Google Maps (оригинальные, свободные от чужих прав). Подписи: белая обводка, адаптивная плотность по зуму, поддержка кириллицы и латиницы.
- Страны и столицы: названия и флаги, при приближении гербы.
- Маркеры игроков: голова скина в рамке цвета страны. Кэш скинов в атласе, кластеры на дальнем зуме.
- 3D-режим в стиле Google Earth: наклон/вращение камеры, плавный зум, LOD, тени. Эффекты: облака, тени облаков, частицы воды, подсветка при наведении, плавные переходы камеры.
- 3D-здания: детализированные модели, генерируются автоматически из блоков построек (voxel → упрощённый меш), кэшируются, обновляются при изменении построек. Прорисовка только вблизи. В пресете «Производительность» 3D-здания отключены. Бюджет генерации и памяти ограничен, генерация вне основного потока.
- Миры: Overworld, Nether, End и любые кастомные, у каждого своя карта и переключатель миров.
- Подземелья: срезы по высоте со слайдером уровня.
- Открытие: вся карта доступна сразу, без «тумана войны».
- Слои: рельеф, страны и регионы, границы, дороги, рельсы и морские пути, города и улицы, места (POI), живые маркеры игроков, дипломатия, линия фронта и зоны контроля, события, экономика (ресурсы, рынки, торговые пути, цены), кадастр, выборы по регионам, RP-слои.
- Кнопка в интерфейсе клиента открывает карту (встроенный UI), есть также команда. Режимы окна: полноэкранный и окно с изменяемым размером. Клавиши настраиваемые.
- Мини-карта настраивается игроком: вкл/выкл, положение, размер, форма, масштаб, поворот по взгляду или север сверху, прозрачность, набор слоёв.
- Единицы расстояний: километры (1 блок = 1 м), точные значения в блоках в карточках и редакторах.
- Время и часовые пояса: у каждого игрока свой часовой пояс (определяется клиентом, меняется в настройках), часы работы мест хранятся в UTC/привязке к реальному времени и показываются в поясе игрока.
- Язык интерфейса: русский и английский, переключатель. Пользовательские тексты (отзывы, вики) хранятся как написаны, у них кнопка «перевести» (провайдер перевода выбери в Фазе 0, см. допущения).
- Пресеты в настройках: «Красота», «Баланс» (по умолчанию для средних ПК), «Производительность», «RP» (включены слои стран, дипломатии, фронта), «GPS» (приоритет мини-карты и навигации, остальное облегчено), «Свой». Пресет управляет качеством рендера, LOD, 3D-зданиями, эффектами, плотностью подписей, частотой обновления, слоями и миникартой. При первом запуске предложи авто-подбор пресета по замеру производительности.
- Экспорт изображения: скриншот карты и плакат высокого разрешения (тайловая сборка большого изображения без просадки FPS, в фоне).
- Режим стримера: скрывает координаты, личные метки и позиции других игроков.
- Телепорт по клику на карте и свободная камера наблюдателя над миром доступны только админам.

## GPS и маршруты
- Позиция и направление взгляда игрока, компас, координаты, название страны/региона/улицы под игроком. Позиция локального игрока берётся на клиенте без обращения к серверу.
- Поиск по адресам и категориям, тегам, странам, статьям вики и игрокам (поиск игроков с учётом правил видимости), автодополнение.
- Маршрут A→B с несколькими остановками, как в Google Maps. Построение на клиенте по графу, который раздаёт сервер, либо на сервере по запросу (выбери в Фазе 0).
- Виды маршрутов: пешком, лодка, поезд, в том числе комбинированные (пешком + поезд + лодка).
- Оценка времени: с учётом реальной скорости игрока (скользящая средняя по виду перемещения).
- Подсказки поворотов: текст на экране и 3D-стрелка/маркер в мире.
- Отклонение от маршрута: предложить перестроение и перестроить после подтверждения игрока.
- Дороги, рельсы и морские пути рисуются вручную (редактор: линии с привязкой к узлам, типы, односторонние участки, закрытие участков). Из них строится граф маршрутизации. Для режима «пешком» вне дорог предложи разумное поведение (прямая навигация по азимуту/рельефу) и обоснуй.
- Маршруты учитывают войны, закрытые границы и зоны, если так решено правилами (расширяемо через RP-моды).

## Адреса, города и транспорт
- Города — отдельная сущность с границами, районами, улицами и номерами домов. Города и районы задают правители стран, игроки через заявку (модерация) и админы.
- Адрес места: улица и номер дома, привязка к городу/району; геокодирование (адрес ↔ координаты) и обратное.
- Транспорт: линии поездов и лодок со станциями и названиями. Линии добавляют админы, правители стран и игроки через заявку. Расписаний и движущихся составов нет. Платный проезд и билеты позже через RP-экономику (точки расширения в API).

## Страны, регионы и границы
- Страны создают игроки через заявку, администрация одобряет.
- Границы рисуются вручную на карте (редактор полигонов): привязка к вершинам, проверка самопересечений и пересечений с чужими странами, расчёт площади, спорные территории как отдельный статус.
- Внутри страны регионы (провинции/штаты) со своими правителями и статистикой.
- Страница страны устроена как статья Википедии: карточка (infobox) и разделы. Хранится всё: название, флаг, герб, гимн, девиз, столица, форма правления, правитель, население (участники), площадь (считается автоматически), дата основания, языки, религия, валюта, экономика, армия, союзы, враги, договоры, история, города, места, галерея. Часть полей вычисляется автоматически.

## Приватность и секретность
- Позиции игроков видны только по странам: игрок, состоящий в стране, видит на карте всех игроков этой страны. Игрок без страны видит только себя. Админы и модераторы видят всех (допущение). Офлайн-игроки: показывается только регион выхода.
- Страны могут скрывать территории и объекты от других стран. Военные объекты (базы, укрепления) — отдельная категория, видны своей стране и союзникам. Полная разведка через RP-армию добавится позже (заложи точки расширения: механизм «открытия» чужой информации по событию).
- Матрица видимости (своя страна / союзники / остальные / админы) применяется на сервере. Скрытые данные клиенту не отправляются.
- Важно для тайлов: общий кэш тайлов не должен «запекать» секретные объекты. Базовые тайлы содержат только публично видимое, секретные объекты и скрытые территории идут отдельными слоями по правам (или тайлы ключуются классом видимости). Секретные объекты не попадают в 3D-модели, панорамы, поиск и подсказки автодополнения для неавторизованных.
- Личные метки игрока: видимость выбирается при создании (только я / моя страна / выбранные игроки).
- История посещений для рекомендаций хранится только локально у игрока и на сервер не отправляется.

## Дипломатия, войны и завоевание территорий
- Состояния отношений: нейтралитет, союз, война, перемирие, мир, договоры. Типы союзов: военный, торговый, культурный. Показываются слоем дипломатии (цвет границ, значки).
- Объявить войну может только правитель страны. У войны есть лимит по времени с обязательным перемирием. Владение территориями после войны меняется по мирному договору правителей (карта показывает проект договора и применяет его при подписании).
- Нейтральные и демилитаризованные зоны: через договоры и админские защищённые зоны.
- Единица контроля территории — чанк 16×16. Захват зоны через контрольные точки (флаги). На захваченной земле оккупанты могут ломать постройки игроков как в обычном PvP (это осознанное решение владельца).
- Во время войны карта в стиле DeepState Map: заливка контролируемых и оккупированных территорий, чёткая линия фронта, статусы (контролируется / оккупировано / спорная зона), пометки изменений за период. Линия фронта строится из состояния чанков с помощью операций над полигонами (union/difference), с упрощением и валидацией.
- Позиции войск на карте видны всем, но с задержкой (данные устаревают).
- Спроектируй механику завоевания как отдельный дизайн-документ до реализации: контрольные точки (расположение, время захвата, удержание, сброс прогресса), условия объявления войны, перемирие, мирный договор, оккупация против аннексии, баланс (кулдауны, ограничения по численности и времени суток), события для RP-мода армии. Предложи 2–3 варианта с плюсами и минусами и порекомендуй один.
- Каждое изменение пишется в журнал и попадает в историю карты.
- Тревожные оповещения (вторжение, начало войны): сирена и маркер на карте, оповещение в стране.

## Экономика, кадастр и политика
- Экономические слои: ресурсы и месторождения, рынки, торговые пути, цены. Цены в карточках мест берутся из RP-экономики автоматически (API-контракт заложи заранее, на время отсутствия RP-мода работает заглушка).
- Кадастр: земельные участки с владельцами, ценой и историей продаж.
- Политика: слой с результатами выборов по регионам. Формы правления, партии, выборы и армия — данные из RP-модов через API.

## Места (карточки как в Google Maps)
- Название, категория, описание, адрес, координаты, часы работы (по реальному времени, с учётом часового пояса игрока), фото, рейтинг, отзывы, популярные часы, вопросы и ответы, меню/товары/услуги, посты владельца.
- Категории: фиксированный список плюс собственные теги.
- Владелец места: игрок-владелец (назначение через заявку и одобрение), отвечает на отзывы и вопросы, публикует посты (акции, новости; защита фильтром слов, жалобами и rate limiting).
- Меню, товары и услуги: связка с RP-экономикой (товары и цены).
- Популярные часы: график по часам, строится по агрегированной статистике посещений (анонимно, на сервере).
- Вопросы и ответы: отвечают владелец и игроки.
- Бейдж «подтверждённое место»: подтверждает правитель страны.
- Продвижение мест в поиске за внутриигровую валюту (через RP-экономику): прозрачная пометка «продвигается», лимиты, защита от злоупотреблений.
- Рекомендации и топы: топы по рейтингу и категориям, персональные рекомендации. Персональные рекомендации считаются на клиенте по локальной истории посещений, сервер отдаёт только кандидатов (популярное, рядом, по категориям).
- Избранное и списки (как в Google Maps), личные метки с заметками, поделиться точкой или маршрутом с конкретным игроком или своей страной.

## Отзывы, рейтинг и фото
- Рейтинг как в Google Maps: 1–5 звёзд, необязательный текст, средний рейтинг, количество, гистограмма, сортировка (новые, лучшие, худшие), фото в отзывах, ответ владельца.
- Отзывы авторами не редактируются и не удаляются. Один отзыв на игрока на место. Удаление нарушающих правила отзывов только модераторами (допущение).
- Фото: внутриигровые скриншоты кнопкой в интерфейсе карты. Жёсткого лимита числа фото нет, но обязательна техническая защита: сжатие и перекодирование, ограничение размера, дедупликация, миниатюры и ленивая подгрузка, мониторинг и квота диска, модерация вместе с заявкой.

## Панорамы улиц (аналог Street View)
- Автоматические панорамы по дорогам. Снимают клиенты игроков во время движения по нарисованным дорогам, шаг 16 блоков. Съёмка фоновая, с ограничением нагрузки (в пресете «Производительность» отключена или урежена).
- Панорамы сжимаются (кубическая карта низкого разрешения в эффективном формате), дедуплицируются, хранятся с квотой диска и политикой хранения. Передача на сервер в фоне, с лимитами на игрока и сервер.
- Игроки в кадре показываются, ники скрываются (клиент отключает ники над игроками на время съёмки).
- Скрытые объекты и военные базы не снимаются. Сервер раздаёт клиентам зоны запрета съёмки и отклоняет загрузки из них.
- Защита от подделки: сервер проверяет положение камеры относительно дороги и игрока, rate limits, подпись/проверка формата. Выборочная ручная модерация панорам.
- Обновление панорам по запросу владельца или модератора: участок дороги помечается «требует обновления», следующий проезжающий клиент снимает заново.
- Просмотр: 3D-обзор улиц в клиенте, переход по шагам вдоль дороги, мини-карта положения.

## Вики
- Полный набор шаблонов статей плюс собственные: страна, регион, город, место, персона, организация, событие, война, договор, закон, религия, технология, лор и т.д. Админы создают новые шаблоны.
- Разметка (заголовки, списки, ссылки, изображения-скриншоты, карточки), привязка к странам и POI, история правок и откат, внутренние ссылки.
- Навигация: портал, «статья дня», избранные статьи, дерево категорий и теги. Страницы обсуждения как в Википедии.
- Статьи о странах правит любой участник страны через модерацию. Чтение и правка прямо в клиенте (экран вики, редактор).
- Внешние ссылки разрешены всем, но публикуются только после модерации: списки доменов, предупреждение перед переходом, без автооткрытия.

## Игроки, профили, события и уведомления
- Профиль игрока: карточка со страной, ролью и статистикой. Репутация авторов карты: значки, рейтинг и награды за вклад.
- События на карте: отметки (праздники, выборы, войны, ивенты), без календаря.
- Уведомления: решения по заявкам, события своей страны, события рядом, подписки на объекты/страны/события.
- Обратная связь в игре: кнопка «сообщить о проблеме» (с опциональным приложением диагностики) и голосование за идеи (статусы, модерация идей админами).

## История карты (таймлапс)
- Автоснапшоты по расписанию: границы, дипломатия, линия фронта, места, дороги, города. Хранятся бессрочно с прореживанием старых (дельты, политика хранения), с учётом диска.
- Интерфейс в клиенте: шкала времени, воспроизведение, перемотка, сравнение двух дат, особенно для фронта войн.
- Откат изменений: ручной откат любого объекта через историю версий (откат всей карты на дату не нужен).

## Админка и модерация
- Всё управление только внутри Minecraft: интерфейс карты, команды и экраны модерации. Сайта нет.
- Личность игрока = UUID на сервере. Whitelist (UUID) и роли: owner / admin / moderator (по категориям: страны, места, вики, фото и панорамы, отзывы, идеи) / trusted / player.
- Экран админа с очередью и статистикой, инструменты массового редактирования (с предпросмотром и откатом).
- Админы: добавлять, править, удалять объекты, страны, статьи и шаблоны; админские защищённые зоны; телепорт и камера наблюдателя.
- Trusted: правят вики и места напрямую, изменения публикуются сразу, попадают в журнал и могут быть откатаны.
- Остальные: заявки на страну, место, линию транспорта, город, правку, внешнюю ссылку → очередь модерации → одобрить / отклонить / вернуть на доработку, уведомление игроку о решении.
- Лимит заявок: 10 в сутки на игрока, с защитой от обхода.
- Команда модерации более 20 человек: очередь с захватом задачи (чтобы не обрабатывали дважды), распределение по категориям, фильтры и сортировка, эскалация, статистика работы, audit log.
- Audit log: каждый модератор видит записи своей категории, админы шире, владелец сервера всё.
- Фильтр запрещённых слов (чёрный список, нормализация обходов) плюс ручная модерация. Кнопка «пожаловаться» на любой контент. Наказание за злоупотребления: временный бан на редактирование (срок, причина, апелляция).
- Уведомления модераторов: в игре и Discord-вебхук (только исходящие запросы, краткие сообщения без личных данных, пакетирование, rate limiting, секрет в env, сбои не влияют на мод).

## Интеграция с RP-модами
- RP-моды (экономика, политика и выборы, армия и войны) пишет Claude, поэтому контракт должен быть чётким, версионируемым и самодокументированным (схемы, примеры, тесты контракта).
- Форматы: Rust-крейт (библиотека) и локальный REST/gRPC. Оба слоя поверх одного ядра, без публичных портов (только localhost/unix socket). Все локальные моды доверенные, но API всё равно валидирует входные данные, ведёт журнал и ограничивает скорость вызовов.
- События: CountryCreated, RegionOwnerChanged, BorderChanged, WarDeclared, TerritoryCaptured, CeasefireSigned, TreatySigned, ElectionResult, RulerChanged, PoiCreated, PriceUpdated и т.д.
- Для каждого RP-мода слой карты и точки расширения: экономика (ресурсы, рынки, цены, билеты, продвижение), политика (формы правления, выборы), армия (подразделения, базы, разведка, фронт).

## Аналитика
- Подробная аналитика использования карты: использование функций, открытие карты, поиск, маршруты, производительность клиентов (FPS, время загрузки, попадания в кэш), нагрузка на сервер. Данные псевдонимизированы, без содержимого чата и личных данных, с ограниченным сроком хранения, дашборды для админов. Игроку в игре сообщается, что собирается.

# ФОРМА КАРТЫ: КРУГЛАЯ ВО ВСЕХ МИРАХ
Требование владельца: карта круглая в любом мире. Боевой сервер — конечный мир с границей, тестовый — бесконечный.
- Конечный мир (боевой сервер): круглая карта по границе мира, как планета в Google Earth. Изменение границы отслеживается автоматически.
- Бесконечный мир (тест): карта тоже круглая. Настраиваемый радиус R (по умолчанию сгенерированная область или заданное значение), за его пределами карта обрезается по кругу. Радиус можно менять без перегенерации тайлов.
- У каждого мира своя круглая граница.
- Основной режим: 3D-глобус (сфера) в схематичном стиле. Камера вращается вокруг шара, подсветка атмосферы по краю, плавный переход от орбиты к уровню земли.
- Проекция: чётко документированное отображение игровых координат (X, Z) на сферу. Сравни варианты (equirectangular, cube-sphere, азимутальная) по искажениям у полюсов, шву, простоте тайлинга и LOD, выбери один и обоснуй. Сферическая тайловая схема (quadtree) должна поддерживать LOD и кэш так же, как плоская.
- Если граница мира круглая: дополнительный режим круглой плоской карты без искажений.
- Переключатель режимов: Глобус / круглая плоская карта / плоская 2D-карта для точной навигации и редакторов (границы, дороги, города).
- Источник истины — игровые координаты. Расстояния, площади, маршруты и координаты POI считаются в плоскости мира, а не по сфере. Проекция обратима (экран ↔ мир), покрыта тестами на круговое преобразование.
- Тайлы хранятся в мировых координатах, проекция применяется только при рендере, чтобы изменение границы не требовало перегенерации.
- Края и швы: нет видимых швов и обрывов; за границей мира — океан/пустота/стилизованный край. Страны и фронт, пересекающие шов, корректно разрезаются и склеиваются. Подписи не искажаются и не переворачиваются.
- Маркеры и подписи на сфере через instancing, с отсечением обратной стороны шара.

# УЛЬТРА-ОПТИМИЗАЦИЯ И МАСШТАБ (5000+)
## Изоляция от игрового тика
- Мод в игровом потоке только собирает минимальные события (позиция, смена чанка, изменение блока) и кладёт их в ограниченную lock-free очередь (bounded MPSC) с коалесингом: для игрока хранится только последняя позиция, для чанка — флаг «грязный».
- Вся обработка (тайлинг, генерация 3D-зданий, сериализация, БД, сеть, снапшоты, приём панорам) — в отдельном рантайме/процессе (sidecar), общение через shared memory/unix socket/локальный канал. Падение или тормоза карты не должны влиять на игру. Для каждого модуля свой выключатель (feature flag).
- Никаких блокирующих вызовов, аллокаций в горячем пути, глобальных Mutex на тике. Предвыделенные буферы, арены, zero-copy там, где возможно.
## Синхронизация игроков на карте
- Позиции карты обновляются с частотой 1–4 Гц (не 20 Гц тика), квантуются (например, до 1/8 блока), передаются дельтами в компактном бинарном формате (FlatBuffers/MessagePack/свой формат), не JSON.
- Раздача по каналам стран: клиент получает только позиции своей страны (см. приватность), плюс interest management по видимой области. На дальнем зуме вместо маркеров кластеры.
- Данные карты идут по игровому сетевому слою (или отдельному каналу, по результатам Фазы 0) с приоритетом ниже игровых пакетов. Бюджет трафика на игрока, backpressure, отбрасывание устаревших кадров, сжатие (zstd), быстрое восстановление после реконнекта через снапшот + дельты. Отдельные ограничения для тяжёлых потоков (панорамы, плакаты, 3D-здания).
- Масштабирование: архитектура по итогам Фазы 0 (один процесс / шарды / сервера за прокси), между sidecar-процессами шина событий (NATS/Redis). Игроки со всего мира: региональные узлы/прокси, если архитектура позволяет.
- Идемпотентность и порядок: номера последовательностей, снапшот + журнал изменений, чтобы клиент всегда сходился с истиной.
## Тайлы, 3D и панорамы
- Схематичный стиль даёт лёгкие тайлы (векторные или упрощённые). Используй это.
- Dirty-tracking чанков, debounce и приоритетная очередь перерисовки (сначала то, что видят игроки); фоновый рендер с лимитом CPU.
- Версионируемые тайлы с ключом класса видимости (для секретных зон), клиентский дисковый кэш с LRU и лимитом, который игрок задаёт сам, подгрузка только видимых тайлов, предзагрузка по направлению движения, серверный кэш, предварительная генерация нижних уровней, ленивая — верхних.
- 3D-здания: автоген из блоков, упрощение, LOD, instancing, meshopt/Draco-сжатие, потоковая подгрузка, жёсткие бюджеты вершин на сцену. Только вблизи, отключаемо пресетом.
- Панорамы: сжатие, дедупликация (перцептивный хэш), миниатюры, потоковая подгрузка по шагу вдоль дороги, квоты диска, политика хранения, лимит скорости загрузки.
## Клиентский рендер
- Целевое железо — средний ПК. Instancing для маркеров, frustum/occlusion culling, батчинг draw calls, декодирование в фоновых потоках, бюджет памяти GPU, адаптивное качество по FPS, пресеты в настройках.
- Деградация качества, а не FPS: карта не должна просаживать игру.
## Данные
- На проде PostgreSQL + PostGIS (гео-индексы), пулы соединений, подготовленные запросы, пагинация по курсору, кэш горячих данных, материализованные агрегаты рейтингов и популярных часов.
- Запись отзывов, заявок, аналитики и панорам через очередь, чтобы пик нагрузки не ронял БД.
- Хранилище скриншотов, панорам и снапшотов: сжатие, дедупликация, политика хранения, квоты диска.
## Наблюдаемость и проверка
- tracing + Prometheus-метрики + Grafana-дашборды по всем бюджетам (тик-оверхед, лаг маркеров, размер очередей, число подписчиков, трафик на клиента, диск, нагрузка панорам и 3D).
- Нагрузочные тесты: swarm из 5000+ виртуальных клиентов (ботов, говорящих на протоколе карты) и симуляция 5000 движущихся игроков в нескольких странах. Сценарии: пик входа (тысячи сразу при релизе), массовое перемещение, потеря сети, шторм реконнектов, массовая подача заявок, массовая загрузка панорам, война с массовой сменой контроля чанков.
- Регрессионные бенчмарки в CI: сборка падает при выходе за бюджет. Предрелизный чек-лист (обязателен, так как выкатка всё сразу).
- По итогам: отчёт «бюджет → измерено → узкие места → что сделано».

# ЗАПУСК: СТЕНД → ПРОД
- Домашний ПК (мощный) — стенд для разработки и тестов, не боевой сервер. Перед открытием для игроков переезд на VPS/выделенный сервер, бюджет не ограничен, нужна защита от DDoS на уровне провайдера. Спланируй переезд и проверку на целевом железе.
- Один и тот же код должен работать и на стенде, и на проде: профили конфигов dev/prod, docker compose/оркестрация, без жёсткой привязки к облаку. На стенде допустимы SQLite, in-memory шина событий и локальный кэш. На проде PostgreSQL/PostGIS и NATS/Redis. Путь миграции описан и протестирован заранее.
- Сеть: игроки подключаются только к игровому серверу. Без лишних открытых портов. Для стенда допустим Tailscale (лаунчер Horizon уже использует его для приглашений) или прокси.
- Ресурсы: игровой сервер и sidecar карты делят хост. Лимиты CPU/RAM для карты, приоритет ниже игрового тика, режим «карта уступает игре», при необходимости вынос sidecar на отдельный хост.
- Резервные копии данных карты (включая скриншоты, панорамы и снапшоты): раз в сутки на диск, проверка восстановления, контроль дискового пространства. Полный экспорт/импорт данных карты для переезда сервера.

- CI на каждый релиз Horizon: сборка серверного движка с нативным модом, сборка клиентского мода (или форка), подпись minisign, публикация, тесты совместимости на новом коммите. Тестовый сервер перед обновлением боевого, откат на предыдущий движок.
- Обновление Horizon не должно ломать мод: только именованные hook points, проверка `NATIVE_HOOKS_API`, автоматический отчёт о несовместимости.
