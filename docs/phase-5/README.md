# Фаза 5: тайлер, проекция, схематичный рендер, тема

Начата 2026-11-08, поверх Фазы 4 (ветка `phase-4-game-integration`). Первый срез, фаза не закрыта.

## Архитектура

```text
 файлы региона ─► vexmap-tiler (поток sidecar, 30 с, 50 % времени) ─► tiles/public/<мир>/<уровень>/x.z.vxt
 клиент: TileCache.plan ─► TileWants ─► тик (без разбора) ─► feed ─► TileService (бюджет 64 КБ/с) ─► Tile ─► GPU
```

- Тайл 256×256, байт на пиксель: материал и оттенок. Цвета выбирает клиент, смена темы тайлы не трогает.
- Один фрагментный шейдер на все режимы, таблицы страниц 64×64 (ADR-006, ADR-018).
- Все ADR ниже: **предложено, ждёт подтверждения владельца.**

## ADR-021. Формат тайла

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Растр материал + оттенок, PackBits** | Тема без перерисовки, только `std` | Сжатие слабее zstd |
| Векторные тайлы | Компактнее на дорогах | Рельеф и биомы не векторные, сложный клиент |

## ADR-022. Отрисовка

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Таблица страниц во фрагментном шейдере** | Один код на три режима, нет швов | Пиксельная работа зависит от размера окна |
| Сетка на тайл с проекцией в вершинах | Меньше работы на пиксель | Тесселяция и отдельный код для глобуса |

## ADR-023. Миникарта на тех же тайлах

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Тот же проход и таблицы, что у карты: они никогда не видны одновременно** | Никакого второго набора текстур. Тема, материалы и рельеф те же | Миникарта рисуется только на видимой области, без грубого уровня всего мира |
| Отдельный набор таблиц | Обе видны сразу | Вдвое больше памяти ради случая, которого нет: под открытой картой HUD скрыт |

Таблицы переписываются, только когда вид пересекает границу тайла, или раз в секунду в покое. Поэтому ходьба с миникартой не тратит 0,73 мс на каждый кадр.

## Исправление чтения мира (2026-11-09)

В палитре секции блок без свойств записан просто строкой с именем, а блок со свойствами записан объектом. Читалка понимала только объект, поэтому камень, земля и стоячая вода считались воздухом, а карта показывала кроны деревьев и подземные постройки сквозь землю. На настоящем файле региона после исправления неизвестными остались только несгенерированные чанки.

Файл уже нарисованных регионов теперь называется по правилам рисования (`scan-2.txt`). При исправлении чтения имя меняется, и все регионы рисуются заново.

## Обновление карты вживую (2026-11-09)

Файлы региона попадают на диск только при сохранении мира, поэтому новая местность появлялась с большой задержкой. Теперь сервер региона показывает карте чанки вокруг игроков такими, какие они сейчас.

```text
тик: 8 снимков чанков (native_chunk_snapshot, копия указателя) ─► поток vexmap-live: столбцы, хеш чанка, только изменившиеся
 ─► feed ─► sidecar: копия региона в памяти + чанк ─► те же тайлы и пирамида ─► клиент (проверка ближних тайлов раз в 4 с)
```

- Правила «что видно сверху» теперь одни на файлы и на живые чанки (`classify`, `walk_column` в `proto.rs`).
- Сервер обходит круг радиусом до 8 чанков вокруг игрока за две секунды, ближние чанки первыми. Толпа получает круг поменьше, но не меньше радиуса 2.
- В тике нет чтения блоков: таблица «состояние блока → материал» строится первые секунды по 1024 состояния за тик, дальше тик только копирует указатели.
- Sidecar держит копии 16 последних регионов, поэтому перепад высот на границе чанка рисуется верно. Живой чанк новее файла сохраняется и при следующем сканировании файла.
- Работает под модулем `tiles`. Тайлы получают строго растущую версию, даже две перерисовки в одну секунду.

Стенд, `tools/dev/phase6_test.py`, 2026-11-09, числа предварительные (память стенда неисправна). Блоки менялись командой сервера, папка мира не сканировалась.

| Проверка | Результат |
|---|---:|
| От изменения блока до записи в тайл | 0,83 с и 2,69 с (два изменения) |
| Затем до копии на клиенте | ещё 1,36 с и 0,73 с |
| Тик сервера с модом, один игрок | p50 24 мкс, p99 124 мкс, максимум 925 мкс (было p50 2, p99 около 15) |
| Отключения игрока | 0 |

Не проверялось: толпа игроков и мир с большим числом активных регионов.

## Кнопка полного прогруза (2026-11-09)

Кнопка «Прогрузить» на карте видна тем же, кому разрешена правка сети (админ и владелец). Право проверяет sidecar по базе. Она запускает обход файлов мира сразу и снимает паузы между регионами. Рисуются регионы, которые ещё не нарисованы или изменились на диске, а под кнопками виден счётчик «Прогрузка карты: N из M». Пока идёт прогруз, клиент проверяет и дальние тайлы раз в 4 с, поэтому мир проявляется сразу. Список готовых регионов сохраняется каждые 16 регионов, поэтому перезапуск не начинает всё сначала. Чанки, которые никогда не генерировались, кнопка не создаёт.

## Настройка

| Переменная | Где | Значение |
|---|---|---|
| `VEXMAP_WORLD_DIRS` | sidecar | Папки миров серверов этого хоста, через разделитель путей ОС. Не задана: тайлы только раздаются |
| `VEXMAP_TILE_DIR` | sidecar | Хранилище тайлов, по умолчанию `vexmap-tiles` |
| `VEXMAP_MAP_RADIUS` | сервер региона | Радиус карты в мире без настоящей границы, по умолчанию 16 384 |
| `VEXMAP_DIAG` | клиент | Частота кадров в лог раз в 5 с, для стендового теста |
| `VEXMAP_DEPS` | `stage.py`, тесты | Папка сборки, чтобы git worktree использовал общую `.deps` |

Horizon пишет в лог, когда в прогон вмешался человек. Тест считает такие строки: прогон с `person_touched > 0` не доказывает шаги, которые человек нарушил.

## Неисправная память стенда

**Подтверждено 2026-11-08.** Тест памяти в Windows, 16 ГиБ, 12 потоков, 20 минут: 977 ошибок. Все они в битах 32–39, то есть в одной байтовой линии, и значение остаётся неверным при повторном чтении. Ошибки начались примерно на восьмой минуте.

Оба синих экрана за сутки (`0x1A`, подкод `0x41792`, повреждённая запись таблицы страниц) показывают по одному лишнему биту, 39 и 33, в той же линии. Туда же попадают ошибки в кэше Cargo и сбои `rustc` и линковщика.

Модули F4-3200C16 работают на штатных 2133 МГц и 1,2 В, разгон ни при чём. Какой модуль или слот виноват, программно не определить: нужна проверка по одному модулю.

До замены памяти сборки и замеры со стенда считаются предварительными, в том числе числа этой фазы. Перед нагрузочными тестами их надо повторить.

После оборванной сборки `LNK2019` лечится только `cargo clean -p horizon-client-render -p horizon-client`: удаления инкрементального кэша мало.
